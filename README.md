# Пипил

Локальное приложение для процессов из агентов. На холсте виден вертикальный конвейер: задача переходит от шага к шагу. Шаг может идти сам или остановиться и ждать подтверждения владельца.

Идея оркестратора, шагов агентов, точек проверки и запусков близка к [Paseo](https://github.com/getpaseo/paseo) (Apache-2.0). Код здесь написан отдельно и не копирует исходники Paseo.

Интерфейс на русском. Агенты по умолчанию имитируются, ключ для показа не нужен.

## Запуск

Из корня репозитория, Node.js 22:

```bash
npm install
npm run dev
```

- Интерфейс: http://localhost:5173
- Проверка сервера: http://localhost:3000/api/health

По отдельности:

```bash
npm run start:backend
npm run start:frontend
```

Откройте «Процессы», затем карточку процесса. Отметьте роли задачи: оркестратор, аналитик, архитектор и бэкенд-разработчик уже выбраны, тестировщик подключается отдельно. Укажите папку проекта, если карта, навыки и правила лежат в ней. Нажмите «Запустить». У каждой роли свой новый диалог. Если архитектор спрашивает, конвейер стоит, пока вы не ответите: оркестратор за вас не отвечает.

Навыки, команды и общие правила читаются из `.cursor` этой папки и не вставляются в каждое сообщение. Карта одна на проект. Её читают все роли. Пишет её только оркестратор в конце и только если она изменилась. Остальные роли сообщают, что добавить.

Состояние лежит в `backend/data/state.json`. Удалите файл, чтобы вернуть начальных агентов и процесс.

## Что можно настроить

- Агенты: имя, тип, инструкции и среда (`Имитация` или `Cursor`).
- Навыки: общие или у одного агента.
- Процесс: порядок шагов, какой агент ведёт шаг, режим «Автоматически» или «Ждёт подтверждения», текст передачи следующему.
- Одновременно идёт один запуск.

## Проект

Экран «Проект» в рейке, отдельно от настроек агента. Он показывает три группы выбранной папки: правила Cursor (`.cursor/rules`), навыки (`.cursor/skills`) и конфигурацию MCP (`.cursor/mcp.json`). Файл можно открыть, поправить или добавить. «Сохранить в .cursor» пишет его в эту папку. Живой API Cursor при этом не вызывается.

Ниже блок «Рекомендации». Правило «Запуски на машине пользователя» выключено, пока его не запишут кнопкой «Записать в .cursor». Файл ляжет в `.cursor/rules/запуски-на-машине.mdc`. Само оно не создаётся.

## Токен Cursor

На этом этапе подключение — по API-токену, без OAuth. Токен сохраняется только на сервере:

- переменная `CURSOR_API_TOKEN` в окружении backend;
- или поле в «Настройках», которое пишет `cursorToken` в `backend/data/state.json`.

Браузер не получает токен целиком. В ответе есть признак подключения и, для сохранённого токена, маска из последних четырёх символов. Если токена нет, приложение открывается, а агент со средой Cursor показан как «Не подключён».

Агенты со средой «Имитация» по-прежнему не ходят в сеть. Шаги со средой «Cursor» при сохранённом токене вызывают Cloud Agents API (`POST https://api.cursor.com/v1/agents`, опрос `GET …/runs/{runId}`). Без токена такой шаг завершается ошибкой с текстом на русском. `CURSOR_LIVE=0` отключает сетевой вызов даже при токене. На экране «Проект» можно сохранить несколько локальных папок и файлов `.code-workspace` и выбрать один для запуска.
