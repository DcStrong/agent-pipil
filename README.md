# Пипил

**Пипил** — локальное веб-приложение: визуальный конвейер агентов для задач в вашем проекте. Вы собираете цепочку ролей, запускаете задачу и видите, как она проходит шаг за шагом. Это оркестратор процессов, а не клон или замена Cursor IDE.

Стек: **TypeScript**, **React** (Vite), **Node.js**, **NestJS**. Интерфейс на русском.

## Что умеет

- **Доска задач** — колонки «Новые», «В работе», «На проверке»; перенос в работу запускает выбранный процесс или команду агентов. Ход на доске всегда **имитация** (живой Cursor не вызывается).
- **Процессы и холст** — список процессов, редактор цепочки шагов на холсте: агент, режим шага, связи между шагами, запуск с холста. Одновременно выполняется **один** запуск процесса.
- **Встроенные пресеты** — шесть готовых цепочек: «Фича», «Тестирование», «Рефакторинг», «План», «Баг», «Вопрос»; пресет можно открыть на холсте и сохранить как свой процесс.
- **Агенты и навыки** — настройка агентов (имя, тип, инструкции), среда выполнения **«Имитация»** или **«Cursor»**, общие и персональные навыки.
- **Запуски** — история и экран текущего запуска: диалог шагов, ожидание ответа или подтверждения владельца.
- **Проект** — список локальных путей на машине backend, просмотр и правка файлов `.cursor` (правила, навыки, MCP) без вызова Cursor API.

Состояние (агенты, процессы, запуски, проекты, токен) хранится на сервере в `backend/data/state.json` (путь можно переопределить через `DATA_PATH`). Удаление файла сбрасывает данные к начальному набору.

## Быстрый старт

Из корня репозитория:

```bash
npm install
npm run dev
```

| Сервис   | URL |
|----------|-----|
| Интерфейс | http://localhost:5173 |
| API (health) | http://localhost:3000/api/health |

По отдельности (команды из корневого `package.json`):

```bash
npm run start:backend   # nest start --watch в backend, порт 3000
npm run start:frontend  # vite в frontend, порт 5173
```

Фронт проксирует `/api` на backend (`frontend/vite.config.ts`).

### Переменные окружения backend

Файл `backend/.env` подхватывается **только** при запуске через `nest start` / `npm run start:dev` (скрипты `start` и `start:dev` в `backend/package.json`). При `npm run start:prod` (`node dist/main`) `.env` автоматически не читается — задайте переменные в окружении процесса.

Образец — `backend/.env.example`. Основное:

| Переменная | Назначение |
|------------|------------|
| `PORT` | Порт API (по умолчанию `3000`) |
| `CURSOR_API_TOKEN` | Токен для режима API (альтернатива сохранению в «Настройках») |
| `CURSOR_LIVE=0` | Запрет **живых** шагов со средой Cursor на сервере (в коде блокируются и CLI, и облачный API). Не переключает режим CLI — режим задаётся в настройках |
| `CURSOR_AGENT_BIN` | Полный путь к бинарнику `agent`, если его нет в `PATH` |
| `SIM_DELAY_MS` | Пауза имитации одного шага, мс (по умолчанию `1100`) |
| `DATA_PATH` | Путь к файлу состояния |

## Как пользоваться

1. **Проекты** — в разделе «Проект» добавьте папку репозитория или файл `.code-workspace`. Путь должен существовать на машине, где работает backend. Можно задать **алиас** для отображения в списке.
2. **Процесс** — «Процессы» → новый процесс или пресет → **холст**: расставьте шаги, выберите агента и режим («Автоматически», «Ждёт ответа», «Ждёт подтверждения» и др.), сохраните процесс.
3. **Запуск** — на холсте укажите задачу и проект, нажмите «Запустить». Шаги с режимом вопроса или подтверждения останавливают конвейер, пока владелец не ответит.
4. **Доска** — альтернативный сценарий: создайте карточку, привяжите проект и процесс (или отдельных агентов), перетащите в «В работе».
5. **Настройки** — режим Cursor и токен API (см. ниже).

## Подключение Cursor

Пипил **не** воспроизводит редактор Cursor. Для шагов со средой **«Cursor»** backend вызывает внешний инструмент — по настройкам сервера.

| Режим | Когда использовать | Что нужно |
|-------|-------------------|-----------|
| **CLI** (по умолчанию) | Локальный агент в папке проекта на машине backend | CLI `agent` в `PATH` или `CURSOR_AGENT_BIN`; вход в настройках или ключ `CURSOR_API_KEY`; для шага — сохранённый проект (папка или workspace) |
| **API** | Cloud Agents | Токен в «Настройках» или `CURSOR_API_TOKEN` |

В режиме **CLI** одна задача выполняется так (см. `backend/src/runtime/cursor-cli.ts`):

```text
agent -p --workspace <папка или workspace> "<промпт>"
```

Промпт передаётся аргументом после флагов; флаг **`--trust` не используется**. Рабочая директория процесса — папка проекта или каталог файла workspace.

Авторизация CLI: **вход через Cursor** можно запустить в «Настройках» (backend выполнит `agent login` и сохранит сессию на своей машине) или сохранить ключ **`CURSOR_API_KEY`** (поле `cursorCliApiKey` в `backend/data/state.json`) — он передаётся в процесс `agent` через окружение; достаточно одного из двух способов. Секреты в браузер целиком не отдаются; для сохранённого ключа — маска последних символов.

В режиме **API** backend обращается к Cloud Agents API (`https://api.cursor.com/v1/agents`, опрос статуса run). Токен на сервере не отдаётся в браузер целиком; в UI — признак подключения и маска последних символов для сохранённого токена.

Агенты со средой **«Имитация»** не обращаются к Cursor. На доске задач живой Cursor не вызывается даже при настроенном CLI или токене.

## Ветки репозитория

| Ветка | Назначение |
|-------|------------|
| `main` | Стабильная, готовая версия |
| `dev` | Активная разработка |

Изменения в продукт вливаются в `dev`; в `main` не мержить напрямую без принятого релизного процесса.
